## 2024-05-24 - Vue 2 Reactive Object Batching & Async Race Conditions
**Learning:** In Vue 2 components, clearing a reactive object by iterating through keys and using `this.$delete` triggers an excessive number of reactivity updates. When refactoring async fetching logic, using `Promise.all` over `forEach` might introduce a performance degradation in perceived UX because it awaits the slowest request to finish before updating the view. It also introduces a risk of throwing completely if one request fails.
**Action:** When clearing or re-initializing reactive objects, use direct assignment (e.g., `this.obj = {}`) to trigger a single reactive update. When fixing async race conditions from `forEach` fetching loops, use a local instance variable to track the current ID (e.g., `this._currentFetchId`) and verify the state before applying resolved data via `$set`. This preserves the UX of updating elements individually as they load.
